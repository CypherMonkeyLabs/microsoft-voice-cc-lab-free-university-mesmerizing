Entra ID accounts voice will use

Learn it in 5 minutes

Humans, rooms, and resource accounts are Entra objects. Resource accounts are disabled for sign-in on purpose. They represent an auto attendant or a call queue. They are not a shared mailbox someone should open in Outlook as their daily driver.

Create the object, license it, then grant voice policy. Creating a resource account takes a Teams administrator role and the User Administrator role. Skipping the second role looks like a Teams bug and is an identity-permission miss.

Resource accounts are Entra objects that must not sign in. License them after you create them with both admin roles.

Resource accounts do not sign in. Humans and rooms do.

A colleague reports: Pairing fails because sbc.contoso.com was never verified. Where do you start?

Pairing fails because sbc.contoso.com was never verified. Add the domain, including a sip subdomain, before you pair the gateway. Source: https://learn.microsoft.com/en-us/microsoftteams/direct-routing-plan accessed 2026-10-14.

Which description of onmicrosoft.com domain is accurate?

The default tenant domain. It is not a supported domain for a Direct Routing SBC FQDN. People try it because it already resolves inside Microsoft 365. Source: https://learn.microsoft.com/en-us/microsoftteams/direct-routing-plan accessed 2026-10-14.

A colleague reports: The gateway object is rejected or never becomes healthy. Where do you start?

The gateway object is rejected or never becomes healthy. Use a domain you verified, such as contoso.com. Source: https://learn.microsoft.com/en-us/microsoftteams/direct-routing-plan accessed 2026-10-14.

Glossary

  • Microsoft 365 tenant The boundary that holds Entra ID, licenses, Teams policies, and verified domains for one organization. Config: Confirm the tenant before you run Connect-MicrosoftTeams. Fault: Two engineers edit two tenants and each thinks the other broke the trunk.
  • Verified domain A domain added and proven in the tenant. Direct Routing SBC FQDNs must live on one of these domains. Config: Add the domain, including a sip subdomain, before you pair the gateway. Fault: Pairing fails because sbc.contoso.com was never verified.
  • onmicrosoft.com domain The default tenant domain. It is not a supported domain for a Direct Routing SBC FQDN. Config: Use a domain you verified, such as contoso.com. Fault: The gateway object is rejected or never becomes healthy.
  • Homed online Direct Routing users must be homed in Microsoft 365, not left on a Skype for Business on-premises registrar. Config: Check the user’s registrar before you assign a voice routing policy. Fault: The policy is assigned and the call never leaves the legacy system.

Cross-platform bridges

CUCM

Cisco CUBE is one of the SBC families named in this lab’s certification lesson. A certified release can be the Direct Routing SBC between Unified CM and Teams.

The tenant still needs a verified domain on the SBC FQDN, and the user still needs Teams Phone. The studio translator does not open a live AXL session. Confirm the current certified release before you build.

Webex

Teams Phone and Webex Calling are separate clouds. This lab does not describe a feature that registers a Webex Calling user into a Teams tenant.

A number move is usually a carrier port, a certified SBC, or a meetings interop product. Confirm before relying.

UCCE

Unified CCE stays the ACD until you migrate it. Microsoft’s contact-center articles name Connect, Extend, and Unify. They do not name a UCCE connector in the notes this lab cites.

Voice into Teams is still Direct Routing or Operator Connect. The routing script stays on the contact-center product you bought. Confirm the vendor’s current model. Source: https://learn.microsoft.com/en-us/microsoftteams/teams-contact-center.

Future hooks

Copilot Studio, Azure Communication Services, and Graph are later tracks in this lab. Treat any uncited limit as confirm before relying.
